# 业务结果展示规范

适用于所有产品、查询工具、当前回答及历史会话。展示简化不能改变事实、计算、权限或数据范围。

## 三级信息结构

1. 默认业务结论：本轮对象、相关结果、有证据的关键数值。聊天最多列出5项关键物料，其他进入明细。
2. 业务明细：BOM单耗、逐项需求、库存、缺口、限制物料及核算范围，通过物料表和来源入口查看。
3. 审计证据：来源校验、数据版本、重复处理、业务确认、Tool输入输出、错误诊断及权限绑定保留在后台Evidence；按权限提供来源详情，不当作普通回答。

## 按意图展示

| 类型 | 默认结果 | 不主动附加 |
| --- | --- | --- |
| 产品目录 | 产品名称、编码 | 库存、缺料、产能 |
| BOM | 版本、组成、单耗 | 库存、最大产量、采购 |
| 库存 | 数量、对应物料 | 无关日期、产量 |
| 指定数量生产 | 目标、需求、满足状态、缺口 | 最大产量 |
| 最大数量 | 实际上限、范围、限制物料 | 快照治理条件 |
| 缺料追问 | 已存Evidence中的不足物料、数量 | 无关指标、重复计算 |
| 采购 | 有依据的数量、参数、成本 | 没有价格依据的金额 |
| 来源 | 本次实际计算依据、可追溯记录 | 无关系统状态 |

## 缺失值与部分结论

- null保持null，不转0，不生成空指标或整列无值的表格。已知0必须显示。
- 部分行无记录时保留BOM关系，用“无记录”说明具体业务缺口；不得宣称库存为0。
- 部分物料指标命名为“已核算物料数”“已核算物料产量上限”。正数上限不是完整BOM可生产量。
- 已核实必需物料库存不足1单位用量时，上限0可证明完整BOM无法满足任何正整数数量，无需猜测其他未知库存。
- 读取失败、计算失败、权限拒绝必须保持错误状态，已算BOM需求不能被抹除。
- 每条历史回答按原始问题及对应Evidence渲染；新查询不得改写旧结论。切换产品不得继承其他产品的指标。

## 实现与新增能力要求

`agents/query_presentation.py`提供`presentation.result_type / show_maximum / user_warnings / policy_version`，原始审计警告与Evidence保留。前端适配器选择本轮字段，卡片和表格再防御性过滤空值；不解析answer来生成事实，不按产品编码硬编码界面。

新增Tool必须保留status/data/completeness/provenance/warnings，区分完整与部分范围。新增页面必须通过业务展示回归测试：空值、真实0、部分覆盖、读取失败、明确最大数量、普通查询、切换产品、历史恢复。计算规则仍由Python服务拥有。
