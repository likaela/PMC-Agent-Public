# 企业自然语言回答契约

调用链保持：Planner → 受控 Tool → Evidence → Python 业务表达 → 既有 Response Generator → 持久会话。

## 事实边界

数值、产品、版本、日期、完整性和原始结论只来自已验证 Evidence。模型仍由 `config.get_llm()` 提供，没有第二套模型配置。

Response Generator 接收结构化 evidence、business_decisions 和只读事实语句。模型输出严格 JSON，只能选择事实语句顺序、简洁/简报布局及受控结束语；所有事实语句必须各引用一次。Python 从原语句插入字段，不接受模型自由文本、数字或结论。这样不仅拒绝新增数字，也拒绝把已知数字调换到错误字段。

## 展示与审计分离

BOM 正文概览产品、版本、明细数和已知生效日期；类别仅按已发布名称的明确文字提取。完整行、Decimal 字符串、null、价格、完整性和来源保留在 structured_data / provenance / Evidence。普通正文不罗列全部料号或散列、批次标识、数据库字段。

来源追问复用已保存证据，不重新查询，提供可读的产品及版本引用。详细审计信息仍保留在来源详情中。

## 生产语义

- 证据不足：NOT_APPROVED_DUE_TO_INSUFFICIENT_EVIDENCE，当前不能批准，不等于已经确认库存不足。
- 确定缺料：CANNOT_PRODUCE_DUE_TO_SHORTAGE，保留既有 Tool 缺料结论。
- 库存齐套：仅说明库存满足，不将齐套或采购建议提升为企业开工许可。

当上下文解析阻止计算时，可以只读获取唯一已发布 BOM 的结构证据来解释已知与未知。此操作不选择生产有效日期、不变更版本解析规则、不执行生产计算。多个版本时仍澄清，不自动择一。

## 回退与兼容

模型未配置、超时、JSON 非法、引用遗漏或额外事实字段均回退同一确定性业务模板，不改变 Tool 状态。BOM 概览、来源追问与“主要是什么”等追问复用证据。显式数量变化仍进入原受控分析路径。

演示产品使用独立数据源。公开部署入口禁用外部模型与追踪，直接使用相同的确定性业务模板；事实校验与来源追溯仍然有效。
